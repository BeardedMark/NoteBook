Фильтр Блума — вероятностная структура данных для быстрой проверки принадлежности элемента множеству **без обращения к БД**

**Главная идея**
- **«Да»** → _возможно есть_ (ложные срабатывания допустимы)
- **«Нет»** → _точно нет_ (ошибок не бывает)

**Гарантии**
- 100% корректный ответ только для **«нет»**
- **Ложноположительные** возможны
- **Ложноотрицательных** не бывает

**Как работает**
1. Массив битов (0/1)
2. Несколько хеш-функций
3. При добавлении элемента → выставляются биты
4. При проверке → если хотя бы один бит = 0 → элемента **точно нет**

**Зачем нужен**
- Снизить нагрузку на БД
- Ускорить проверки существования
- Отсеивать заведомо отсутствующие данные

**Типичные кейсы**
- Проверка, есть ли ключ/ID в кеше
- Anti-spam / anti-duplication
- Проверка уникальности перед запросом в БД
- Web / high-load системы

**Минусы**
- Нельзя получить сами данны
- Нельзя удалить элемент (в классической реализации)
- Требует подбора размера и числа хешей

**Расширения**
- Counting Bloom Filter — поддержка удаления
- Scalable Bloom Filter — динамический рост

**Короткая формула в голове**
> «Если фильтр сказал _нет_ — в БД идти не надо.  
> Если сказал _да_ — всё равно проверяй».
