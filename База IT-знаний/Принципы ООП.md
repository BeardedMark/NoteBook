# Объектно-ориентированное программирование (ООП)

**Object-Oriented Programming** — строишь программу из объектов (как из реальных сущностей), а не просто из функций и переменных.

**Мини-мемори:**
1. **Инкапсуляция** — «не лезь внутрь, пользуйся чем дали»
2. **Наследование** — «такой же, но изменённый»
3. **Полиморфизм** — «одна кнопка, разные эффекты»
4. **Абстракция** — «всё равно как, просто сделай»

---

## Инкапсуляция

Прячем внутренности, даём наружу только нужное.  
Зачем: защита данных и контроль логики.

**Пример:**  
Класс «БанковскийСчёт»
- внутри: баланс
- снаружи: методы `пополнить()`, `снять()`  
    Пользователь не может напрямую менять баланс.

---

## Наследование

Один класс расширяет другой.  
Зачем: не дублировать код, строить иерархии.

**Пример:**  
Класс «Животное» → `говорит()`  
Класс «Собака» наследует «Животное» → `говорит()` = "Гав"  
Класс «Кошка» наследует «Животное» → `говорит()` = "Мяу"

---

## Полиморфизм

Один интерфейс — разное поведение.  
Зачем: писать универсальный код.

**Пример:**  
Список животных: `[Собака, Кошка]`  
Вызываем у всех `говорит()`  
Собака → "Гав"  
Кошка → "Мяу"

---

## Абстракция

Выделяем главное, скрываем детали.  
Зачем: менять реализацию без переписывания кода.

**Пример:**  
Интерфейс «Платёж» → `оплатить()`  
Класс «Карта» → своя реализация `оплатить()`  
Класс «Крипта» → своя реализация `оплатить()`
